# Level design and pacing workflow

What should this section teach, test or let the player express?

## When to repeat

For each new level, or after changes to movement, encounters, checkpoints or teaching.
Run one focused pass for the current request; return when new evidence or changed
assumptions make another pass useful. Do not load every reference or rerun every
check on every minor edit.

## Bring forward

The level’s purpose, current controller and camera, layout and prior player observations.
If a previous record exists, review its decisions and unresolved findings before
planning. If it does not, establish a small baseline from the current game and
mark missing evidence explicitly.

## Run the cycle

1. Review the section’s purpose and the last route observations. Identify the expected entry knowledge and the intended new decision. Test spatial assumptions with the installed controller and actual camera, not an imagined movement envelope.

2. Block out a small route or puzzle. Arrange introduction, safe practice and a meaningful variation where that rhythm suits the brief. Plan recovery and landmarks before decorative density.

3. Play and observe route choice, hesitation, repeated failures and checkpoint use. Separate a control or camera problem from a spatial problem; test one layout or encounter hypothesis at a time.

4. Revise the section and replay entry, optional paths, checkpoint return and exit. Use the real movement and collision rules to confirm reachability. Review neighboring sections when the change alters pacing.

## Verify and decide

Confirm the player can perceive the next useful action without an author’s explanation. Check intended and unintended routes, puzzle reset and recovery. A connected navigation graph does not establish that teaching or pacing works.

A new dash changes jump distances. Revisit previously tested gaps and recovery routes before adding obstacles tuned to the old controller.

## Leave a record for the next pass

A route and teaching plan, pacing notes, observed failure points and replay scenarios.

Keep the section goal, routes, taught mechanic, pacing intent and observed failure locations. Retain a compact replay route and controller/camera assumptions so later changes can challenge them.

Use an existing project note or the handoff when no durable note tool is offered.
Keep facts separate from assumptions. The next pass should be able to recover
what was tried, why it was chosen and what the evidence established.
