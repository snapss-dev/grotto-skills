# Core game design workflow

Which rule or choice would make the intended experience clearer or more interesting?

## When to repeat

After testing the core loop, or when verbs, goals, challenge or progression change.
Run one focused pass for the current request; return when new evidence or changed
assumptions make another pass useful. Do not load every reference or rerun every
check on every minor edit.

## Bring forward

The intended player experience, current rules and observations from recent play.
If a previous record exists, review its decisions and unresolved findings before
planning. If it does not, establish a small baseline from the current game and
mark missing evidence explicitly.

## Run the cycle

1. Restate the player fantasy and the current action–consequence–decision loop. Compare it with the last design pass. Retain creator-approved choices and identify where actual play differs from the intended experience.

2. Choose one hypothesis about agency, learning, risk or reward. Define what a player would do differently if it is true. A self-directed sandbox can use expressive goals without a score, timer or terminal victory.

3. Adjust the relevant rule or feedback relationship, using the loop and feedback references as needed. Keep unrelated difficulty, reward and presentation changes separate so the observation remains interpretable.

4. Observe the same scenario with the changed build. Ask players to act before explaining the rule; distinguish understanding from preference. Use the outcome to keep, revise or remove the change.

## Verify and decide

Check whether the player can perceive the consequence and make a meaningful next decision. Include the relevant failure or recovery path. A complete rules description and successful browser boot do not prove that the loop is enjoyable.

If players collect a resource without spending it, test a meaningful use before increasing the reward amount. Revisit the loop when the new use changes player priorities.

## Leave a record for the next pass

A concise loop description, design hypotheses, observed player choices and the next experiment.

Keep the current loop, one hypothesis, the scenario, observed behavior and the design decision. Preserve unresolved questions instead of treating a single player’s response as a general retention result.

Use an existing project note or the handoff when no durable note tool is offered.
Keep facts separate from assumptions. The next pass should be able to recover
what was tried, why it was chosen and what the evidence established.
